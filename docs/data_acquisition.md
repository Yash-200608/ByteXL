# ByteXL — Data Acquisition & Research Map

Research date: 2026-10-08. Pass 1 wrote sections A, C, F, O and the checklist. Pass 2 (same day) re-checked the
PARTIAL / UNVERIFIED rows against primary pages and added sections B, D, E and G–N. The **Pass 2 corrections** list
below records every status or fact that changed.

**How to read the status column.** `VERIFIED` means the source page itself was opened and the stated facts were read
from it. `PARTIAL` means the resource was confirmed to exist via its official page or paper, but some details (file
layout, licence, latest version) were not read from the primary source. `UNVERIFIED` means it came only from a
mirror, search snippet or third-party page. Nothing below should be cited as fact beyond its status.

**Resource types** are kept distinct: *Dataset* (records you download), *Terminology* (code system), *IG* (FHIR
implementation guide — rules and examples, not clinical data), *Tool*, *Reference list* (official list/PDF), *Paper*
(describes data; the paper is not the data), *Benchmark*.

## Section A — Executive summary

### What ByteXL needs

ByteXL reads Indian medical documents and turns them into verified, normalised, FHIR-shaped records. Its data needs fall
into five groups:

1. **Reference data that decides facts** (deterministic Python): lab test names → LOINC, units (UCUM), reference ranges,
   Indian brand → generic composition, dosing grammar.
2. **Standards and validators** for the output: the NRCeS FHIR Implementation Guide for ABDM, its package, and a FHIR
   validator.
3. **Evaluation documents with ground truth**: real-looking Indian lab reports, prescriptions (printed and handwritten)
   and discharge summaries, including difficult photos and scans.
4. **Longitudinal data** to exercise the timeline, trends and medication reconciliation.
5. **Hindi resources** for the plain-language summaries.

### What already exists in the repository

| Asset | Content | Limitation |
|---|---|---|
| `data/reference/lab_tests.csv` | 51 lab tests with aliases, LOINC, sex-specific adult ranges, critical limits, curated EN/HI meanings | Ranges are adult-only and not sourced per row; aliases are hand-written |
| `data/reference/medicines.csv` | 103 Indian brands → generic, strength, form, class | Tiny versus the Indian market (hundreds of thousands of SKUs) |
| `samples/` | 5 synthetic documents (text PDF, photo, scan, printed and handwriting-style prescription) | All one fictional patient, generated by `scripts/make_samples.py`; no real layouts |
| `tests/fixtures/synthetic_truth/` | Ground truth for the 5 samples | Synthetic; F1 0.96 on these says little about real Indian documents |

### Most important gaps

1. **No real Indian document images with ground truth.** This is the biggest credibility gap: every accuracy number
   so far is on our own synthetic samples.
2. **Medicine coverage**: 103 brands versus a market where community datasets list 195k–250k+ products.
3. **Lab alias coverage**: 51 tests, with aliases written by hand rather than mined from real Indian reports.
4. **Bundles never validated** against the official NRCeS package.
5. **No genuine Indian handwriting** data with medicine and dosage labels.

### Highest-value external sources found

- **NidaanKosha-100k** (Eka Care, India): 6.84M lab readings from 100,000 Indian reports, with test name *as printed*,
  value, unit, printed range, specimen, age, sex and LOINC (581 codes). VERIFIED. This is close to a ready-made source
  for ByteXL's alias table.
- **Eka medical-records parsing validation set** (India): 288 images of Indian lab reports and prescriptions. VERIFIED.
  This is the most direct real-world evaluation set found.
- **NRCeS FHIR IG for ABDM v6.5.0** and the HL7 FHIR validator. VERIFIED / PARTIAL.
- **LOINC 2.83** (released 2026-08-19, 112,405 concepts) with the Consumer Name file. VERIFIED.
- **SNOMED CT India Drug Extension** ("Common Drug Codes for India"), latest release notes dated 2026-08-31, free to
  affiliates in India via MLDS. PARTIAL.
- **Indian medicine catalogues** on Kaggle (195k–250k+ rows, with salt composition). UNVERIFIED (seen via mirrors);
  the licence must be checked.

### Recommended acquisition order (summary of Section O)

NRCeS package + validator → NidaanKosha → Eka validation set → LOINC 2.83 → Indian medicine catalogue (licence check
first) → Jan Aushadhi + NLEM lists → SNOMED CT India (MLDS) → handwriting sets → Synthea → credentialed US corpora
(MIMIC-IV-Note, n2c2) for research.

### Details

**1. NRCeS FHIR Implementation Guide for ABDM, v6.5.0** — IG, Tier 1.
- *Contains:* FHIR R4 (4.0.1) profiles. The document profiles are DiagnosticReportRecord, PrescriptionRecord,
  DischargeSummaryRecord, OPConsultRecord, ImmunizationRecord, HealthDocumentRecord, WellnessRecord and InvoiceRecord,
  plus examples and a downloads page. The page labels 6.5.0 as the "current published version" and shows
  "Generated 2025-05-08". [nrces.in/ndhm/fhir/r4](https://nrces.in/ndhm/fhir/r4/index.html)
- *Why ByteXL needs it:* ByteXL tags bundles with NRCeS profiles but has never validated them against the package.
- *Module:* FHIR, ABDM export.
- *Usage:* validation and reference, not training.
- *Weakness:* the page shows both "active" and "Draft as of 2025-05-08". Re-check the version directory before
  pinning. The ABDM developer forum refers to the package at `nrces.in/ndhm/fhir/r4/package.tgz`; I did not download it.

**2. HL7 FHIR Validator** — Tool, Tier 1.
- *Contains:* `validator_cli.jar` (needs Java). Load the NRCeS package as an IG and validate each bundle.
- *Evidence:* ABDM forum threads recommend this route, and also the web validator at fhir.healthit.gov. They note that
  the web validator sometimes rejects NRCeS's own sample records, so cross-check with the CLI.
  [devforum thread](https://devforum.abdm.gov.in/t/fhir-validator-used-in-abdm/7862)
- *Module:* FHIR and ABDM.
- *Benefit:* a "FHIR validation rate" metric for the benchmark, and a demo claim backed by evidence.
- *Usage:* validation, run in CI.

**3. NidaanKosha-100k-V1.0** (Eka Care) — Dataset, Tier 3 (publisher-released, India).
- *Contains:* 6,844,304 readings from 100,000 lab reports from Indian diagnostic facilities, covering 2023 to March 2025.
  Columns are `document_id`, `age`, `gender`, `test_name` (as extracted), `value`, `unit`, `display_ranges` (the range
  printed on the row), `specimen` (12 classes) and `loinc` (581 codes). Parquet, 176 MB, CC BY-SA 4.0.
  [Hugging Face](https://huggingface.co/datasets/ekacare/NidaanKosha-100k-V1.0) ·
  [AIKosh](https://aikosh.indiaai.gov.in/home/datasets/details/nidaankosha_100k_v1.html)
- *Why ByteXL needs it:* it is real-world evidence of how Indian labs *print* test names and units, already paired
  with LOINC.
  - It can grow `lab_tests.csv` from 51 tests and hand-written aliases to frequency-ranked aliases for the top few
    hundred LOINC codes.
  - It shows which units actually occur in India, for example `/cumm`, `lakh/cumm` and `mill/cumm`.
  - The printed ranges give a distribution to sanity-check our reference ranges against.
- *Module:* normalization (LOINC mapping, units, ranges) and the trends test data.
- *Weaknesses:*
  - The values were machine-extracted by Eka's vision LLM and the LOINC codes were "assigned automatically", so the
    data is not human-verified. Use it to propose aliases and have a person review them.
  - There are no images and no report dates.
  - CC BY-SA is share-alike, which may apply to tables derived from it. Check before redistributing derived files.
- *Usage:* normalization and reference-data mining, plus synthetic report generation (realistic value distributions).
  Do **not** use it as extraction ground truth.

**4. Eka medical_records_parsing_validation_set** — Dataset (evaluation), Tier 3, India.
- *Contains:* 288 images of Indian lab reports and prescriptions in "diverse formats and templates encountered in
  India". Columns are `image`, `md5_image`, `sample_prompt`, `rubrics` and `document_type`. MIT licence. Gated:
  you must accept contact-sharing on Hugging Face. Uploaded 25 July 2025.
  [Hugging Face](https://huggingface.co/datasets/ekacare/medical_records_parsing_validation_set)
- *Why ByteXL needs it:* it is the only real Indian document-image set with expert-derived evaluation material that I
  found. It turns "F1 0.96 on our synthetic samples" into a number on real layouts.
- *Module:* OCR, classification, extraction (end-to-end evaluation).
- *Weakness:* the ground truth is published as LLM-generated **rubrics**, not field-level JSON, so field F1 is not
  directly computable. Either score against the rubrics or hand-label fields for a subset.
- *Usage:* held-out test set only. Never tune prompts on it.

**5. LOINC 2.83** — Terminology, Tier 1.
- *Contains:* 2.83 was released 2026-08-19 with about 3,080 new concepts (about 1,260 of them drug/toxicology) and
  112,405 total; the next release is listed for February 2027. The LOINC FHIR Terminology Service has been updated to
  2.83 ([forum](https://forum.loinc.org/t/loinc-terminology-service-updated-for-version-2-83/3136)). The previous
  release, 2.82 (February 2026), had 109,325 concepts (97,314 active). Downloads need a free account; the 2.82 zip was
  ~85 MB. Accessory files include ConsumerName.csv (alpha status) and per-language LinguisticVariants. There is no Hindi
  variant listed in the results I saw.
  [loinc.org](https://loinc.org/) · [Release notes](https://loinc.org/kb/loinc-release-notes) ·
  [Getting LOINC](https://loinc.org/get-started/getting-loinc/)
- *Module:* LOINC mapping, FHIR Observation coding.
- *Usage:* reference. Confirm the 51 existing codes are active, and pull display names, units and classes.
- *Caveat:* LOINC says Consumer Names are for display only and must not be used for mapping local terms to LOINC.

**6. Indian medicine catalogues on Kaggle** — Datasets, Tier 3/4. UNVERIFIED. They were seen via the baselight.app
mirror; in pass 2 the Kaggle pages returned only their titles to the fetch tool, so licence, row count and update date
are still unconfirmed. Open them in a logged-in browser before use.
- [A-Z Medicine Dataset of India](https://baselight.app/u/kaggle/dataset/shudhanshusingh_az_medicine_dataset_of_india)
  (shudhanshusingh): "250K+" allopathy products with prices as of November 2022.
- [Indian Medicine Data](https://baselight.app/u/kaggle/dataset/mohneesh7_indian_medicine_data) (mohneesh7):
  ~195,600 rows with product name, salt composition, manufacturer, price and description.
- [11000 Medicine Details](https://baselight.app/u/kaggle/dataset/singhnavjot2062001_11000_medicine_details): ~11,825
  rows scraped from 1mg.
- *Why ByteXL needs it:* this is the only route found to **50,000+ Indian brand → composition** records, including
  combinations. ByteXL already supports merging `medicines_extended.csv`.
- *Module:* medicine mapping, reconciliation (combination ingredients).
- *Weaknesses:*
  - The data appears to be scraped from pharmacy sites, so the licence and terms of use are unclear.
  - Salt strings need parsing into structured ingredients and strengths.
  - The data is stale (2022). Use it as candidate data checked against official generic lists (#9, #10).

**7. SNOMED CT India Drug Extension — "Common Drug Codes for India"** (NRCeS) — Terminology, Tier 1. PARTIAL.
- *Contains:* a national extension adding drugs available under Indian health programmes. It is modelled by active
  ingredient, dose form, package and concentration. Release notes exist for 2020-12-21, 2025-06-20, 2026-03-13,
  2026-06-15 and 2026-08-31 (the latest, inferred from file names).
  [2026-08-31 release notes (PDF)](https://nrces.in/download/files/pdf/doc_SnomedCT-IndiaDrugExtension-PRODUCTION-ReleaseNotes_Current-en-US_IN1000189_20260831.pdf)
- *Why ByteXL needs it:* it gives official Indian drug codes for FHIR MedicationRequest, which ABDM profiles favour
  over free text.
- *Weakness:* it covers generics and medicinal products; brand coverage is not confirmed.
- *Access:* via MLDS with an Affiliate Licence (free in India).

**8. SNOMED CT International Edition via NRCeS** — Terminology, Tier 1.
- *Access:* India is a SNOMED International member. Register at MLDS, accept the Affiliate Licence, and the download
  arrives in about 4–5 business days. Affiliates must file an annual usage report.
  [NRCeS SNOMED CT](https://nrces.in/standards/snomed-ct) ·
  [SNOMED India member page](https://www.snomed.org/members/india)
- *Module:* FHIR Condition and procedure coding, condition grounding.
- *Usage:* reference. **Start registration today**, because of the multi-day wait.

**9. PMBJP / Jan Aushadhi product list** — Reference list, Tier 1. PARTIAL.
- *Contains:* the official annexure lists 2,110 generic medicines under PMBJP as of 31 December 2025, with drug code,
  name and unit size. [PIB PDF (Feb 2026)](https://static.pib.gov.in/WriteReadData/specificdocs/documents/2026/feb/doc202626781701.pdf)
  The official site is janaushadhi.gov.in; I did not find a direct CSV/Excel download there.
- *Module:* medicine mapping, as a government-sourced list of generic names and strengths.
- *Weakness:* PDF table extraction is needed, and the list has no brand names.

**10. NLEM 2022** — Reference list, Tier 1. PARTIAL.
- *Contains:* 384 medicines in 27 therapeutic categories, tagged Primary, Secondary or Tertiary. Launched 13 Sept 2022.
  It is also the basis of the DPCO Schedule I price controls.
- *Source:* a copy of the PDF is hosted by the National Health Systems Resource Centre at
  [qps.nhsrcindia.org/.../nlem2022.pdf](https://qps.nhsrcindia.org/sites/default/files/2022-09/nlem2022.pdf) (located,
  not opened). No mohfw.gov.in or cdsco.gov.in URL was found. Summarised by
  [BioVoice](https://biovoicenews.com/384-drugs-included-in-nlem-2022-34-new-drugs-added/).
- *Usage:* a coverage target. Every NLEM generic should resolve in ByteXL's medicine table.

**11. UCUM** — Terminology, Tier 1. PARTIAL.
- *Source:* ucum.org (the essence XML file was not confirmed in this pass). HL7 publishes UCUM naming metadata at
  [terminology.hl7.org](https://terminology.hl7.org/5.0.0/CodeSystem-v3-ucum.xml.html).
- *Module:* unit normalization and FHIR `Quantity.system`.
- *Gap:* Indian lab units such as `lakh/cumm` need explicit mapping rules to UCUM (`10*5/uL`). NidaanKosha (#3) shows
  which ones occur.

**12. ICD-11 MMS 2026 release + ICD-API** — Terminology / API, Tier 1. PARTIAL.
- *Contains:* WHO's 2026 release, announced 16 Feb 2026. Spreadsheet download via the browser, and the API at
  icd.who.int/icdapi. Licence CC BY-ND 3.0 IGO.
  [WHO release note](https://www.who.int/news/item/16-02-2026-icd-11-2026-release)
- *Module:* diagnosis coding in FHIR Condition (optional; ABDM also uses SNOMED CT).

**13. Doctor's Handwritten Prescription BD dataset, v2** — Dataset, Tier 2/3. VERIFIED.
- *Contains:* 4,680 word images (128×128) of handwritten medicine names from Bangladeshi prescriptions, in 78 classes
  of 60 images each, with CSV/XLSX labels. CC BY 4.0, stated as "for educational and research purposes". Version 2
  published 10 Aug 2026. [Mendeley Data](https://data.mendeley.com/datasets/zjjtptvn6f) (DOI 10.17632/zjjtptvn6f.2)
- *Module:* handwriting OCR and medicine-name recognition (evaluation).
- *Weaknesses:*
  - The images are single-word crops, with no dosage and no full-page layout.
  - The brands are Bangladeshi (Napa, Maxima…), many of which differ from Indian brands.

**14. MIRAGE public subset** — Dataset, Tier 3. VERIFIED.
- *Contains:* the MIRAGE paper used 743,118 simulated, annotated Indian handwritten records from 1,133 doctors across
  52 specialties. Only **100** records are public, at
  [tavishm/100-handwritten-medical-records](https://huggingface.co/datasets/tavishm/100-handwritten-medical-records)
  (37.8 MB of JPEGs).
- *Contents of the public subset:* a single `image` column — **no labels, no licence stated**.
  [Paper](https://arxiv.org/html/2410.09729v1)
- *Usage:* handwriting stress tests, after you hand-label medicines and doses. Clarify the licence with the authors
  before redistributing.
- *Note:* this is the closest public material to Indian doctor handwriting found.

**15. ClinOCR-Bench** (July 2026) — Benchmark, Tier 2. VERIFIED.
- *Contains:* 384 scanned clinical documents from 16 templates, free of protected health information, in 6 subsets of
  64: normal, handwriting, poor, rotated, tables and mixed. 56 exemplars are held out for one-shot use and 328 are
  scored.
  - Ground truth is a human-audited transcription per document. The repo does not mention bounding boxes or
    line/word levels.
  - MIT licence. Available as a GitHub release zip (no account needed) or via
    `load_dataset("ClinOCR-Bench/ClinOCR-Bench", "<subset>")`.
  - [GitHub](https://github.com/ClinOCR-Bench/ClinOCR-Bench) · [arXiv 2607.03650](https://arxiv.org/abs/2607.03650)
- *Module:* OCR robustness across failure modes (blur, rotation, tables).
- *Weakness:* US-style documents; transcription only, so no box-level (IoU) scoring.

**16. IndianDrugMCQA** (Eka Care) — Benchmark, Tier 3. VERIFIED.
- *Contains:* 1,512 brand → generic or salt-composition multiple-choice questions across 20+ therapeutic classes.
  MIT licence. [Hugging Face](https://huggingface.co/datasets/ekacare/indian_drug_mcqa)
- *Usage:* a cheap evaluation of brand → generic resolution. Convert the questions to lookups and measure coverage of
  ByteXL's medicine table.

**17. Synthea** — Synthetic generator, Tier 1 (open source). PARTIAL.
- *Contains:* lifelong synthetic patients, exported as FHIR R4 (bulk ndjson optional), C-CDA and CSV.
  - The latest numbered release is **v4.0.0** (dated "05 Mar"; the year is not shown on the page). It adds US Core 7 to
    the R4 exporter and **requires JDK 17+**.
  - A rolling `master-branch-latest` build is dated "18 Aug".
  - [Releases](https://github.com/synthetichealth/synthea/releases)
- *Module:* timeline, trends and reconciliation load tests; FHIR round-tripping.
- *Weaknesses:*
  - The data is US-centric (Massachusetts demographics, US Core, RxNorm).
  - It produces no document images. Render documents from it with `scripts/make_samples.py`-style templates.

**18. RxNorm** — Terminology, Tier 1. PARTIAL.
- *Contains:* monthly releases (first Monday of each month; the latest seen was May 2026) in RRF format. A free UMLS
  licence is needed for the full set; the "Current Prescribable Content" files need none.
  [Files page](https://www.nlm.nih.gov/research/umls/rxnorm/docs/rxnormfiles.html)
- *Usage:* the ingredient / strength / dose-form *model* and normalised ingredient names. It does not cover Indian
  brands.

**19. MIMIC-IV-Note 2.2** — Dataset, Tier 1, credentialed. PARTIAL.
- *Contains:* 331,794 de-identified discharge summaries (145,915 patients) and 2,321,355 radiology reports. Access
  needs PhysioNet credentialing, CITI training and a DUA. [PhysioNet](https://physionet.org/content/mimic-iv-note)
- *Use for ByteXL:* discharge-summary section structure, summarization research, and medication-list extraction.
  Credentialing takes days, so this is research-phase only.
- *Weakness:* US hospital style; no Indian brands or units; text only (no images).

**20. n2c2 2018 Track 2** — Dataset under a DUA, Tier 1. PARTIAL.
- *Contains:* annotations of medications with their signature attributes (dosage, strength, frequency, route, duration,
  form, reason) and adverse drug events. Best end-to-end F1 was 0.8905.
  [Challenge page](https://n2c2.dbmi.hms.harvard.edu/challenge/2018-track-2-ade-medication-extraction) ·
  [JAMIA 2020](https://pubmed.ncbi.nlm.nih.gov/31584655/)
- *Use:* the field schema and evaluation design for dosing extraction.
- *Weakness:* US notation. It has no `1-0-1`, `BD` or `HS`-style Indian shorthand at the density of Indian
  prescriptions.

**21. Indian reference-interval literature** — Papers, Tier 2. PARTIAL.
- **IFCC multicentre study** (CCLM 2018): 512 healthy Indians, 33 biochemistry analytes.
  [doi 10.1515/cclm-2018-0152](https://www.degruyterbrill.com/document/doi/10.1515/cclm-2018-0152/html)
- **Chennai haematology study** (JCDR, 500 adults). [jcdr.net](https://www.jcdr.net/ReadXMLFile.aspx?id=2630)
- **ICMR** has an open call for a national reference-interval study for children and adolescents. It notes that most
  ranges in use come from Western populations.
  [ICMR EOI PDF](https://www.icmr.gov.in/icmrobject/uploads/Call/1761797370_expressionofinteresteoiicmrstaskforceonestablishmentofreferenceintervalsinindianpopulationteriipphaseii.pdf)
- *Use:* cite these as the source for ranges, and record per-row provenance in `lab_tests.csv`. ByteXL should keep
  preferring the **range printed on the report** and fall back to table ranges only when none is printed.

**22. CoRIL** — Dataset, Tier 2/3. PARTIAL.
- *Contains:* 772,000 sentence pairs across 11 languages in Government, Health and General domains, with Hindi as the
  pivot language. CC BY 4.0. Hosted at
  [HimangY/CoRil-Parallel](https://huggingface.co/datasets/HimangY/CoRil-Parallel) with an EN-HI folder.
  [arXiv 2509.19941](https://arxiv.org/pdf/2509.19941)
- *Use:* Hindi phrasing for the curated meanings and terminology; it could become a Hindi glossary seed.
- *Weakness:* the `HLT` folder is probably the Health subset, but this is inferred, not stated. The size of the Health
  EN–HI subset is not confirmed.

**23. MedMCQA-Indic** (Eka Care) — Dataset, Tier 3. PARTIAL.
- *Contains:* ~50.2k items including Hindi, MIT licence.
  [AIKosh](https://aikosh.indiaai.gov.in/home/datasets/details/medmcqa_indic.html)
- *Use:* Hindi medical vocabulary only. It is exam QA, so do **not** use it for the explanation style (diagnostic
  framing).

**24. Patient-summary hallucination dataset** (`ann-pt-summ` 1.0.0, PhysioNet) — Dataset, Tier 1/2, credentialed.
VERIFIED.
- *Contains:* span-level hallucination annotations by two medical annotators for 100 doctor-written and 100
  LLM-generated patient summaries. Each source is a MIMIC-IV-Note Brief Hospital Course, released as
  Hallucinations-MIMIC-DI and Hallucinations-Generated-DI. Code at
  [stefanhgm/patient_summaries_with_llms](https://github.com/stefanhgm/patient_summaries_with_llms).
  [PhysioNet](https://physionet.org/content/ann-pt-summ/) · [arXiv 2402.15422](https://arxiv.org/html/2402.15422v1)
- *Use:* the annotation scheme (span offsets and error types) for ByteXL's own summary-grounding test set; run its
  checker on these summaries as an external sanity check.
- *Weakness:* needs PhysioNet credentialing. The authors note that "hallucinations" in doctor-written summaries are
  often legitimate added knowledge.

**25. MedRepBench** (Baidu, 2025) — Benchmark, **not released**. PARTIAL.
- *Contains:* ~1,900 real Chinese medical report images, with fields for name, value, unit, reference range and
  abnormal flag. The paper says the release will come "upon acceptance".
  [arXiv 2508.16674](https://arxiv.org/html/2508.16674v1)
- *Use now:* its field-level recall methodology matches ByteXL's lab schema. Watch for the release.

**Searched but not recommended:** Med-HALT and MedHallu
([2307.15343](https://arxiv.org/pdf/2307.15343), [2502.14302](https://arxiv.org/pdf/2502.14302)) test hallucination
on exam-style QA, not grounding of summaries against a source document. HiMed (Hindi medical QA) and Indian Liver
Patient-style tabular sets add little to ByteXL's pipeline.

## Section F — India data gap

**Question: what does ByteXL need that Western datasets such as MIMIC cannot provide?**

| Need | Why Western data fails | Best India-specific source found | Remaining gap |

## Section L — Data schemas

These schemas extend what ByteXL already stores (`app/schemas.py`) with provenance fields needed for evaluation.

**Common fields** (every annotated field):

```json
{
  "document_id": "",
  "source_dataset": "eka_validation | mirage_subset | bytexl_synthetic | ...",
  "page": 1,
  "field": "results[3].value",
  "raw_text": "",
  "value": null,
  "bbox": [0, 0, 0, 0],
  "bbox_space": "page_pixels@200dpi",
  "ocr_confidence": 0.0,
  "confidence": 0.0,
  "verified": false,
  "annotator": "",
  "reviewed_by": ""
}
```

**Lab report:** `document_id, facility, referring_doctor, collected_on, reported_on, patient{name, age_years, sex},
results[{printed_name, canonical_name, loinc, value, value_text, unit, ucum_unit, printed_range, ref_low, ref_high,
flag_printed, flag_computed, specimen, bbox}]`

**Prescription / handwritten prescription:** `prescriber, registration, facility, date, complaints[], diagnoses[],
medicines[{printed_name, brand, generic[], strength, form, dosage_raw, schedule{morning, noon, night, prn},
timing_raw, food_relation, duration_raw, duration_days, instructions, bbox}], advice[], follow_up, handwritten:
bool, handwriting_scope: none|partial|full`

**Discharge summary:** `facility, attending_doctor, admission_date, discharge_date, diagnoses[], presenting_complaints[],
hospital_course, procedures[], investigations[<lab result>], discharge_medicines[<medicine>], allergies[],
follow_up, advice[]`

**Medicine (reference CSV):** `brand, generic, ingredients[{name, strength, unit}], form, route, manufacturer,
snomed_ct_in, rxnorm_ingredient, atc, source, source_version, verified`

**Patient / Encounter / Observation:** follow FHIR R4 Patient, Encounter and Observation with NRCeS profiles; keep a
`derived_from: {document_id, field_path}` extension so every Observation traces back to its page and box.

**OCR box:** `{document_id, page, line_id, text, confidence, polygon[[x,y]x4], bbox[x0,y0,x1,y1]}`

**Confidence annotation:** `{field, model_confidence, ocr_match, ocr_confidence, retry_penalty, final, reason,
queued_for_confirmation: bool}`

**Summary grounding annotation** (modelled on ann-pt-summ):
`{summary_id, lang, spans[{start, end, text, error_type: invented_number|invented_date|invented_medicine|
changed_dose|unsupported_diagnosis|unsupported_inference|missing_abnormal|wrong_normalization}]}`

## Section M — Evaluation benchmark design

| Task | Metric | Formula | Test set |
|---|---|---|---|
| Document classification | accuracy, macro-F1 | correct / total | Eka (document_type) + synthetic |
| OCR | CER, WER | edit distance / reference length | ClinOCR-Bench per subset; BD crops (word accuracy) |
| Field extraction | field P / R / F1, exact match, normalized exact match | P = correct / predicted, R = correct / expected | hand-labelled Eka subset + synthetic truth (existing `scripts/eval.py`) |
| Bounding boxes | mean IoU, % fields with IoU ≥ 0.5 | area(∩) / area(∪) | hand-labelled subset (needs boxes; none public) |
| Lab normalization | flag accuracy; unit-conversion exact match | correct flags / results | synthetic + NidaanKosha-derived cases |
| LOINC mapping | top-1 accuracy, coverage | correct codes / mapped tests | NidaanKosha pairs (after human review) |
| Brand → generic | accuracy, coverage | correct generic / brands queried | IndianDrugMCQA converted to lookups |
| Dosage interpretation | per-slot exact match (morning/noon/night/PRN, food relation, duration days) | correct slots / slots | hand-built sig-line set (≥300 Indian notations) |
| FHIR generation | validation pass rate; error count per bundle | bundles with 0 errors / bundles | all generated bundles vs NRCeS 6.5.0 |
| Summary grounding | unsupported-claim rate; invented-number/date/medicine rates; abnormal coverage | flagged spans / summaries; covered abnormal / abnormal | ByteXL grounding set annotated with Section L schema; ann-pt-summ for external comparison |
| Hindi | reviewer adequacy/fluency (1–5); terminology accuracy; Devanagari ratio | mean score; correct terms / terms | 100 summaries reviewed by a Hindi speaker |
| Medication reconciliation | duplicate-detection P / R | true alerts / alerts; true alerts / true duplicates | Synthea + synthetic multi-document patients with planted duplicates (incl. combinations) |

**Hallucination rate** = summaries with ≥1 unsupported span / summaries. Report the safety checker's own rejection rate
separately from the post-checker rate, so the checker's value is visible.

## Section N — Failure-mode data

| Failure mode | Where it exists | Gap / recommendation |
|---|---|---|
| Blurry / low-quality photos | ClinOCR-Bench `poor`; Eka set (real photos, likely) | Add phone photos taken under poor light with consent |
| Skew / rotation | ClinOCR-Bench `rotated` | ByteXL deskew already; measure on this subset |
| Low contrast, shadows, folds | ClinOCR-Bench `mixed` (artifact types not itemised) | Augment synthetic samples (shadow, fold, JPEG artefacts) |
| Stamps, signatures | Not confirmed in any set | Add to synthetic generator |
| Handwriting | ClinOCR-Bench `handwriting`; MIRAGE subset; BD crops | No Indian page-level labelled set; hand-label MIRAGE |
| Crossed-out medicines | None found | Synthetic: render strike-through lines; expect the confirm queue to catch them |
| Abbreviations (OD/BD/TDS/HS/SOS) | Indian prescriptions only (MIRAGE, Eka) | Build the sig-line test set (Section M) |
| Unusual units (lakh/cumm, mill/cumm) | NidaanKosha `unit` | Mine and map to UCUM |
| Missing reference ranges | NidaanKosha (`display_ranges` nullable) | Test the fallback to table ranges |
| Multiple languages | none for Hindi/English medical documents | Collect locally |
| Tables | ClinOCR-Bench `tables`; PubTabNet (generic) | Measure row-reconstruction errors |
| Multi-page reports | not confirmed in any set | Synthetic two-page lab reports |
| Duplicate medicines | ByteXL samples (metformin in two documents) | Plant more in Synthea-derived patients |
| Conflicting lab values | none | Synthetic: same test twice in one report with different values |
| Incomplete documents | none | Synthetic: crop headers/footers |
